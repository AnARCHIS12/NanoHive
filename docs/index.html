NanoHive Secure Edition

NanoHive Secure Edition est un reverse proxy d'habillage visuel autonome pour Audiobookshelf (ABS). Il injecte un thème moderne et soigné directement dans les pages web d'Audiobookshelf sans modifier ni altérer votre serveur ABS source.

Édition Durcie & Privée
Cette édition a été purgée de toute dépendance tierce indiscrète (abs-tract, scraping Goodreads, synchronisation Hardcover, Google Fonts, télémétrie sociale). Elle fonctionne 100% hors-ligne en circuit fermé.

🎨 Look Cinématique

12 palettes de thèmes sombres raffinées, couleurs d'accentuation sur-mesure, typographie système native haute lisibilité.

🛡️ Zéro Fuite Réseau

Aucun appel externe vers Google Fonts ou des CDNs. Content Security Policy (CSP) stricte bloquant toute tentative sortante.

⚡ Port Isolé 13379

Aucun risque de conflit avec le port générique saturé 8080. Se cale naturellement à côté du port officiel ABS (13378).

📱 Réactivité Mobile Totale

Menu tiroir optimisé, boutons adaptés au tactile, navigation fluide et pas de débordement d'éléments.

Différences avec le NanoHive Original

Le projet upstream d'origine comprenait de multiples fonctionnalités superflues et bavardes sur le réseau. Voici un comparatif direct :

Fonctionnalité NanoHive Upstream (Original) NanoHive Secure Edition
Port hôte par défaut 8080 (conflits récurrents) 13379 (dédié et sans collision)
Polices de caractères Requêtes à fonts.googleapis.com Polices système natives (Zéro requête externe)
Scraper Goodreads (abs-tract) Conteneur Go + scraping Amazon/Goodreads Supprimé à 100%
Relais Hardcover Relais Nginx GraphQL vers api.hardcover.app Supprimé à 100%
Partage social d'écoute Collecte et partage de "qui lit quoi" entre comptes Désactivé / Purgé (Vie privée préservée)
Headers de sécurité Basiques CSP stricte, X-Frame-Options, no-sniff

Démarrage Rapide

Le déploiement prend moins de deux minutes via Docker Compose. Il vous suffit d'insérer le conteneur devant votre serveur Audiobookshelf.

docker-compose.yml 
services:
  audiobookshelf:
    image: ghcr.io/advplyr/audiobookshelf:latest
    restart: unless-stopped
    expose:
      - "80" # Pas besoin de publier sur l'hôte si seul le thème dialogue avec

  abs-theme:
    image: ghcr.io/rodzalendo/nanohive-abs-theme:latest
    # Ou compilation locale : build: .
    restart: unless-stopped
    depends_on:
      - audiobookshelf
    ports:
      - "13379:80" # Port d'accès web du thème
    volumes:
      - nh_theme_data:/data/nh
    environment:
      ABS_UPSTREAM: "http://audiobookshelf:80"
      NH_APP_NAME: "Ma Bibliothèque"
      NH_BASE_THEME: "warm"

volumes:
  nh_theme_data:

Lancez le conteneur en arrière-plan :

Terminal 
docker compose up -d

Ouvrez ensuite votre navigateur sur http://IP_DE_VOTRE_SERVEUR:13379.

Variables d'Environnement

Toutes les variables sont optionnelles à l'exception de ABS_UPSTREAM :

Variable Défaut Description
ABS_UPSTREAM Requis Adresse de votre serveur Audiobookshelf (ex: http://audiobookshelf:80)
NH_APP_NAME "" Nom de votre bibliothèque affiché en haut à gauche
NH_BASE_THEME "warm" Thème de base (warm, slate, black, navy, mocha, pine, etc.)
NH_ACCENT_COLOR "#e0c27a" Couleur d'accentuation en code hexadécimal
NH_MAIN_FONT "system-ui" Pile typographique système native
NH_SHOW_HERO_CAROUSEL "true" Affichage du carrousel de vos écoutes en cours
NH_SHOW_RATINGS "true" Système de notes et d'avis internes auto-hébergés
NH_PROXY_BUFFER_SIZE "16k" Taille des tampons d'en-tête (indispensable pour l'authentification OIDC lourde)

Garantie Zero-Leak & Sécurité

NanoHive Secure Edition a été conçu selon le principe de défense en profondeur :

1. Content Security Policy (CSP) Stricte

Le reverse-proxy Nginx renvoie pour chaque page servie une directive CSP stricte :

Nginx Header 
Content-Security-Policy: default-src 'self'; script-src 'self' 'unsafe-inline' 'unsafe-eval'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; font-src 'self' data:; connect-src 'self' ws: wss:; media-src 'self' blob:; frame-ancestors 'self';

Même si un script tentait d'établir une connexion réseau externe, le navigateur web la bloquera instantanément.

2. Authentification Server-Side via ABS

Toutes les requêtes vers l'API interne du thème (/_nh/api/) sont vérifiées au niveau de Nginx via la directive auth_request. Le jeton Bearer JWT de l'utilisateur est rejoué auprès de l'endpoint /api/me d'Audiobookshelf. Il est impossible de poster des notes ou de modifier des paramètres sans être authentifié par ABS.

Reverse Proxy & OIDC

Si vous placez NanoHive derrière un reverse-proxy HTTPS (Nginx Proxy Manager, Traefik, Caddy, Cloudflare Tunnels) :

Support OIDC Garanti
NanoHive préserve fidèlement l'en-tête X-Forwarded-Proto d'origine. Les connexions via OpenID Connect (Google, Authentik, Keycloak) ne génèrent plus d'erreur de callback d'origine croisée.

Exemple de configuration Caddy :

Caddyfile 
livres.mondomaine.com {
    reverse_proxy localhost:13379
}

FAQ & Dépannage

Pourquoi avoir choisi le port 13379 ?

Le port standard officiel d'Audiobookshelf est 13378. Utiliser 13379 évite toute collision avec les nombreuses applications qui accaparent 8080 (Traefik, Tomcat, Pi-hole, etc.).

Les applications mobiles ABS fonctionnent-elles toujours ?

Oui. L'application mobile Audiobookshelf sur Android et iOS communique directement avec l'API standard d'Audiobookshelf à travers le proxy sans aucune altération.

Où sont stockées les données du thème ?

Toutes les données (vos notes internes, vos jaquettes de séries personnalisées, votre logo) sont stockées dans le volume persistant /data/nh.
